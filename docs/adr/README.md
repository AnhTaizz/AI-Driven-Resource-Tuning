# Architecture Decision Records

Use ADRs for durable decisions that materially affect architecture or research validity.

Examples:

- choosing group split vs temporal split;
- choosing event-log parsing vs REST-only collection;
- changing the canonical execution schema;
- adopting a new experiment tracker;
- changing the recommendation objective/guardrail;
- switching the primary model formulation.

Do not create ADRs for trivial refactors.
